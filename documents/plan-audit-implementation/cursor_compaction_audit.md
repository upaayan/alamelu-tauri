### Findings

**CC-P1-01 — MEDIUM — Bridge path: "absent tools ⇒ empty" is necessary but not sufficient; the plan must commit to the bridge gate rather than leave it conditional.**
Owner requirement: no toolCall may escape a summary request; smallest fix; prefer existing mechanisms.
Evidence: normalizing an omitted `context.tools` to an empty set fixes the native path completely (router `resolveNativeReplayDisposition` → `inactive_trace`, drain `partitionNativeToolsByActiveContext` → all inactive → `"handled"` → loop continues to `run.done` → text `stop`; Cursor executes its native tools itself, the adapter only mirrors them). But `bridge-tool` events are not partitioned at all (`drain.ts:286-291`), and the summary agent is created with an MCP bridge exposing every live non-overlapping Pi tool (`bridge-server.ts:50-58`). One `pi__*` call by Cursor during summarization still yields `toolUse` and the identical Pi error, and the pending MCP call sits unresolved until the run is disposed. Plan B.3 words this as "if the generic omitted-tools correction is insufficient", which the source already answers: it is insufficient for the bridge branch.
Smallest remedy (plan text, not code yet): state definitively that when the per-call tool snapshot is defined and empty, the acquire for that call must not attach the bridge MCP server. The existing path already handles this: `createRun` with an empty snapshot produces `enabled=false` → `bridgeRun = undefined` (`cursor-session-agent.ts:427-430`), which also drops `includePiBridgeGuidance` and the tool manifest automatically (`turn-prepare.ts:284-304`). This needs only a way to pass "empty snapshot" through `acquireSessionCursorAgent` → `createSessionAgentEntry` → `registeredBridge.createRun`. Record the consequence: the pool key includes the live bridge signature (`buildBridgePoolKeySuffix`), so a bridge-less summary agent shares the normal pool key; that is acceptable because `session_compact` invalidates it on success and the next normal turn's context divergence resets it on failure (`planCursorSessionSend` → `resetAgent`). The alternative (reject bridge requests in the drain via the existing `cancelPendingPiToolCallId`) is a fallback only; it leaves pi__ tools advertised to the model and produces tool errors mid-summary.
